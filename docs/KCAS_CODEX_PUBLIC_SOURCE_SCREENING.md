# Codex Public-Source Client Screening

Agreed 3 October 2026. This clarifies the existing acceptance handoff; it does not
create a PEP register, buy a provider subscription or launch Codex automatically.

## Workflow

1. Client -> Client acceptance (`/clients/{id}/onboarding`) -> Request Codex review.
2. Designated Compliance users open the Home task and copy its Codex handoff.
3. In the separate authorised Codex session, research actual client evidence and
   perform live Google or equivalent searches for the client and relevant natural
   persons. Joint/entity names alone do not cover their beneficial owners or agents.
4. Assess supported roles and relationships under FIC Act Schedules 3A/3B/3C.
   Investigate credible adverse information separately. PEP/PIP status alone is not
   misconduct, a sanctions designation or an automatic refusal.
5. Retain search queries/engine, opened source URLs/titles, source dates where
   available, actual check time, identity comparisons, findings and limitations.
   Use public context to resolve namesakes, not private IDs/accounts/contact data
   in public search queries. Check underlying sources, not snippets alone.
6. Save separate PepPip and AdverseInformation results through authorised KCAS
   services with Codex as performer. A supported result means no relevant finding
   in the sources checked, not an exhaustive guarantee. Failed searches, unavailable
   sources and unresolved identities remain genuine gaps; retain earlier history.
7. Validate recorded results, prepare the substantive KI summary and applicable
   enhanced measures, and leave acceptance to the actual authorised KI.

Sanctions/TFS uses the current applicable official FIC/UN lists and source version.
It is not replaced by these searches. Automatic official-list monitoring is a
separate pending enhancement, not implemented by this handoff clarification.

## Existing Tasks and Verification

Re-select Request Codex review on an unchanged pending review to refresh its brief
and the shared Home task without creating another request or changing the original
request date. Historical completed handoffs and KI decisions remain unchanged.

Focused onboarding regression coverage checks live-search instructions, separate
outcomes, underlying-person scope, privacy, source/time capture, unavailable-search
handling, official-list separation and the existing pending-task refresh contract.
No database migration or automatic client screening result is created by this change.

Verification: all nine ClientOnboardingServiceTests pass, including shared pending
task refresh and the unchanged actual-KI decision, evidence and scope gates.

## Regulatory Basis

FIC PCC 51 paragraphs 2.2 and 3.1-3.6 discuss independent research/open sources,
source reliability/currency and the absence of an endorsed commercial listing.
Its older terminology must be read with the current FIC Act Schedules 3A/3B/3C
and sections 21F-21H, not used to restore superseded category/time definitions.

Source: https://www.fic.gov.za/wp-content/uploads/2023/09/2021.12-PCC-PCC-51-FPPO-DPIP.pdf
